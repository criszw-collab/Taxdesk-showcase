# Suggested demonstration: 3 to 5 minutes

This is a guide for a future live demonstration or screen recording. No recorded demo video is included in this repository.

Use a fictional client profile, example.org email addresses and synthetic financial figures. Keep terminal setup codes, passwords, OAuth settings and personal notifications out of the recording.

1. **Introduce the workflow.** Show the staff dashboard and explain the purpose: organizing tax questions, planning estimates, records and correspondence.
2. **Show a client account.** In a separate browser profile, open a fictional client's portal. Explain that staff and client sessions have different permissions.
3. **Ask a simple question.** Submit “What is tax?” and show its processing state, saved response and unverified-answer label when applicable. A live demonstration requires the local model to be running; do not represent controlled test responses as live inference.
4. **Store a document.** Upload a synthetic text file. Explain that uploads are stored for advisers and are not automatically read by the AI.
5. **Prepare a supported estimate.** Use fictional wages and withholding in the direct planning form. Show the calculation assumptions and PDF download.
6. **Return to staff work.** Show a linked document or engagement. Save an adviser answer and show the client view updating.
7. **Close with scope.** Explain that the prototype is local, the source is private and remote hosting/document-reading AI are planned rather than completed features.

Optional closing sentence:

“TaxDesk demonstrates how I connect accounting workflows, local language models, deterministic Python tools and client access controls in a working prototype.”
